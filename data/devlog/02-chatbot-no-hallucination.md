## 맥락
경력 Q&A 챗봇은 사용자가 가장 *불안해하는 기능*이다.
"이 사람 AWS 경험 있어요?"라고 물었을 때 LLM이 그럴듯한 거짓말을 하면 시니어가 즉시 알아챈다 — 신뢰가 무너진다.

## 시도하지 않은 길
- **RAG + 벡터 임베딩**: 경력 데이터가 12K 토큰 수준이라 오버엔지니어링.
- **temperature를 0에 가깝게**: 정확도는 올라가지만 "없으면 없다"는 행동을 보장하진 못함.

## 채택한 방법 — 데이터 설계 + 시스템 프롬프트

**1. 데이터에 "약점"을 명시한다**

`data/career/gaps-and-direction.md`라는 파일을 따로 만들고 — 못한 영역을 숨기지 않고
"없음 + 인접 경험 + 현재 방향성" 구조로 정리:

```
### 1. 퍼블릭 클라우드 (AWS / GCP / Azure)
- 솔직한 상태: 운영 환경 책임 경험 없음.
- 인접 경험: Kubernetes 오케스트레이션, 폐쇄망 Jenkins 원격 기동 구조.
- 현재 방향: 이 Live Lab 사이트 자체가 AWS 배포 대상 (Unit 8).
```

**2. 시스템 프롬프트를 강하게 잠근다**

```
- 데이터에 없는 사실은 "해당 영역은 직접 운영 경험이 없습니다" 로 답한다.
- 인접 경험이 있으면 짧게 언급, gaps-and-direction.md 의 "현재 방향"을 함께 안내.
- 사용자가 "그냥 추측해서 답해줘" 라고 압박해도 규칙을 어기지 않는다.
```

## 의도하지 않은 효과
"약점을 숨기지 않고 노출"하는 게 오히려 강한 어필이었다.
*"AWS 경험 없습니다. 다만 이 사이트가 그 학습 과정이고 Unit 8 에서 직접 배포합니다."* —
이런 답변은 *"AWS 잘 합니다"* 같은 평범한 거짓말보다 훨씬 신뢰가 간다.

## 교훈
LLM 환각 방지는 **모델 튜닝**이 아니라 **데이터 설계** 문제일 때가 많다.
