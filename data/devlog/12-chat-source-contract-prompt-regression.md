## 문제

경력 Markdown 전체를 시스템 프롬프트에 넣고 "데이터에 있는 사실만 답하라"고 지시해도 모델 응답은
자유 형식 문자열이었다. 답변 끝의 파일명 표기도 선택 사항이라 서버는 다음을 구분할 수 없었다.

- 실제 파일을 근거로 한 답변
- 존재하지 않는 파일명을 모델이 만든 답변
- 내부 프롬프트가 섞인 응답
- 사용자가 규칙 무시를 요구해 생성된 허위 경력

낮은 temperature와 강한 지시는 출력 변동성을 줄일 뿐 검증 경계를 만들지 않는다.

## 응답 계약

모델 출력 형식을 JSON 객체 하나로 제한했다.

```json
{
  "answer": "한샘 EAI에서 50개 이상의 인터페이스를 담당했습니다.",
  "evidence": [
    {
      "source": "projects/01-hanssem-eai.md",
      "line": 12
    }
  ],
  "grounded": true
}
```

애플리케이션 시작 시 공개 가능한 경력 Markdown의 상대 경로와 내용을 문서 snapshot으로 만든다. 시스템
프롬프트도 시작 시 고정되므로 두 기준의 수명 주기를 맞췄다. 매 요청마다 파일 시스템을 다시 순회하지 않는다.

`grounded=true` 답변은 다음 조건을 모두 만족해야 한다.

1. JSON 형식과 answer 길이가 유효하다.
2. evidence가 1개 이상, 최대 3개다.
3. 모든 source가 실제 문서에 존재한다.
4. line이 해당 source의 실제 범위에 있고 비어 있지 않은 원문 줄을 가리킨다.
5. answer에 내부 프롬프트 구분자나 규칙 원문이 포함되지 않는다.

하나라도 실패하면 모델의 원문을 노출하지 않고 고정된 보류 응답으로 전환한다. 외부 API에는 원문 line을 그대로
노출하지 않고 검증된 source만 `answer/sources/grounded` 계약으로 반환한다.

## 프롬프트 공격 이중 방어

입력 단계에서는 명시적인 한국어·영어 공격을 LLM 호출 전에 거부한다.

- 이전 지시나 규칙 무시
- 시스템 프롬프트·내부 지시 출력
- 존재하지 않는 경력 생성·추측
- 정치·종교 의견 요구

이렇게 하면 알려진 공격에 외부 API 비용을 쓰지 않는다. 입력 정책을 우회하더라도 출력에 `[경력 데이터]`,
`===== FILE:` 또는 내부 규칙 문구가 포함되면 source ID가 유효해도 폐기한다. 로그에는 질문이나 응답
원문 대신 `prompt_attack`, `sensitive_topic`, `prompt_material` 같은 reason만 남긴다.

## 회귀 평가

CI에서 네트워크 없이 다음 데이터셋을 실행한다.

- 지시 무시·프롬프트 탈취·허위 경력 생성 공격 6건
- 정치·종교 의견 요청 3건
- 차단하면 안 되는 정상 경력·아키텍처 질문 5건
- 정상 evidence, 허위 source, 빈 evidence, 범위 밖 line, 빈 line, 잘못된 JSON, code fence JSON, 내부 규칙 출력

차단 사례만 늘리면 정상 질문까지 거부하는 규칙이 되기 쉽다. 따라서 "프롬프트 인젝션 대응은 어떻게
했나요?"처럼 보안 경험을 묻는 정상 질문도 허용 회귀 사례로 함께 유지한다.

## 남은 한계

source와 line 검증은 근거 위치의 원문 존재를 보장하지, 그 줄이 답변의 모든 수치와 주장을 의미적으로
뒷받침한다는 것까지 보장하지 않는다. 정규식 입력 정책도 알려진 명시적 패턴을 빠르게 차단하는 1차 방어라서 변형된
표현은 우회할 수 있다.

다음 단계는 답변 주장과 검증된 인용 간 의미 일치 평가, 실제 모델 버전으로 실행하는 선택적 품질 평가,
그리고 운영에서 관찰한 실패 유형을 익명화해 회귀 데이터셋에 추가하는 것이다.
