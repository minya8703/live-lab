## 증상

사이트 https://minya.life 가 갑자기 521 (Cloudflare: Web server is down). 4 시간 전 SSL/TLS 통계엔 TLS 1.3 649 hits 정상이었음. 그 사이 무언가가 origin 을 죽임.

AWS 콘솔 → EC2 → Instances → **"인스턴스 없음"**. ap-northeast-2 (서울) region 맞음. 인스턴스가 사라진 거지 region 함정도 아님.

동시에 로컬 `.ssh\livelab` 키도 사라짐 — 이건 별개 이유 (PC 정리 중 삭제 추정).

## 의심한 가설 (시간순)

1. **해킹** — 외부 침입자가 EC2 를 terminate 했나? 가능성 낮음. 공격자가 자기에게 이득 없는 terminate 를 할 이유 없음. Mining 이면 인스턴스 *추가* 후 비용 폭증이 흔적이지 *제거* 가 아님
2. **Region 함정** — 다른 region 에 살아있나? 콘솔 우상단 서울 region 확정 — 제외
3. **본인 실수 terminate** — 어제 SSL Mode 만지면서 다른 탭에서 잘못 누름? 가능성 있지만 *해킹 의심 먼저 검증* 부담
4. **AWS 측 자동 조치** — Free Tier abuse, 결제 실패 등

## 결정적 단서

AWS 콘솔 **Billing** 페이지 상단 **"권장 조치 (3)"** 섹션에 빨간 X 와 함께:

> ❌ **만료된 결제 방법**
> 기본 결제 방법이 만료되었습니다. 인보이스 결제 실패 및 AWS 서비스 중단을 방지하려면 카드 정보를 업데이트하거나 다른 결제 방법으로 전환하세요.

이 한 문장이 시나리오를 확정. CloudTrail 까지 갈 필요도 없었음.

## 진짜 원인

AWS 의 결제 실패 자동 정책:

| 단계 | AWS 가 한 일 |
|---|---|
| ① 월간 결제 시도 → 카드 만료로 실패 | — |
| ② 등록 이메일로 알림 (놓침 또는 스팸함) | — |
| ③ Grace 기간 7~14일 | 기다림 |
| ④ Grace 종료 → **인스턴스 자동 terminate, EBS 정리** | 영구 소실 |
| ⑤ 계정 부분 정지 — 신규 launch 거부 | 권장 조치 배너 표시 |

⚠ **핵심 함정**: 6 개월 크레딧 모드 ($200) 라 비용 $0 이라도, **활성 결제 수단**은 별도 요구. 크레딧만으로 인스턴스 유지 안 됨.

## 해결

1. **결제 수단 업데이트** — Billing → Payment methods → 새 카드 등록 → Default
2. **계정 정상화 확인** — 권장 조치 배너 사라짐
3. **EC2 재배포** — 인스턴스는 영구 소실, 런북 그대로 새로 launch
4. **Elastic IP attach** — 재발 시 IP 갱신 부담 0
5. **Cloudflare DNS A 레코드 → 새 EIP** 로 수정

복구 총 시간: 약 60 분. 코드는 GitHub 에 살아있고, 회고도 마크다운으로 git 관리라 자산 손실 0.

## 일반화한 룰

> **AWS 인스턴스 유지에는 세 가지가 모두 활성이어야 한다 — 크레딧, Free Tier 한도, 결제 수단.**

세 가지 중 하나라도 비활성이면 인스턴스가 사라질 수 있다. 그 중 가장 자주 놓치는 게 *카드 만료 90일 전 알림*.

재발 방지:
- 카드 만료일 캘린더에 90일 전·30일 전 알람
- 또는 *자동 갱신* 옵션 켜진 카드 등록
- **Elastic IP** 로 IP 고정 (다음 재배포 시 DNS 갱신 0 회)
- AMI 스냅샷 주기적으로 (다음 사고 시 분 단위 복구)
