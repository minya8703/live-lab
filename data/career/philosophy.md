# Philosophy — 일하는 방식

## 한 줄
검증에서 시작하고, 안정으로 마무리한다.

## 의사결정 원칙

1. **장애 허용도가 낮은 시스템이 우선**
   - 멈추면 안 되는 인터페이스·결제·정산·인증 영역을 9년 6개월간 다뤘다.
   - "그럴듯한 새로움"보다 "측정된 안정"을 선택한다.

2. **자습 → 돌려보기 → 실무 → 측정**
   - 책만 읽고 멈추지 않는다. 무조건 한 번 돌려보고, 가능하면 실무에 즉시 적용해 수치로 확인한다.
   - Informatica · Appium · Spring Boot 3 · Spring AI 모두 이 순서로 익혔다.

3. **무중단·무장애를 우연으로 두지 않는다**
   - Shell 모니터링으로 한샘 EAI의 3개월 주기 장애 리스크를 사전 차단.
   - Redis CacheErrorHandler · Kafka DLT/FixedBackOff 같은 fallback 구조를 디폴트로.

4. **레거시는 적이 아니라 컨텍스트**
   - MONEX MFA에서 Servlet Filter 패턴으로 레거시 코드 수정 없이 비침투적 통합.
   - ANA 발권에서 NTT 데이터 intra-mart 프레임워크를 먼저 이해한 뒤 메서드 평균 200줄→30줄 리팩터링.

5. **혼자 하는 일도 흔적을 남긴다**
   - 폐쇄망 Jenkins 원격 기동 구조, 일본어 마스킹 테스트 데이터 생성, 비개발자용 OCR 좌표 설정 UI 등 — 다음 사람이 적게 묻도록 도구화.

## 협업 방식
- 인터페이스 표준은 한 번 합의하고 11종 패턴으로 문서화 (한샘 EAI).
- 코드 리뷰는 "왜 이렇게 했는지"를 묻는다 (ANA 발권에서 평균 메서드 길이 합의).
- 비개발자(현업)에게도 의존성을 만들 수 있는 UI를 만든다 (Invoice OCR 좌표 설정 웹 UI).
