U5 · Kafka 처리량 라이브 데모

"Kafka 7토픽 · DLT · FixedBackOff 재시도"를 라이브로 증명

Kafka 3.7 KRaft 모드 · 3 파티션. Producer가 주문 이벤트를 발행하면 Consumer가 소비하고, 17의 배수 orderId는 의도적으로 실패시켜 FixedBackOff 500ms × 3회 재시도 → DLT 라우팅까지 흐름을 그대로 봅니다. 사용자 Betax SaaS 운영 패턴 동일.

발행 후 약 500ms 간격으로 상태를 폴링합니다. 17의 배수인 orderId(약 5.9%)가 의도적 실패 → 재시도 → DLT로 흐릅니다.

실행 전

이 데모가 측정하는 것

  • Producer가 livelab.orders 토픽(3 파티션)으로 OrderEvent를 발행. JsonSerializer + acks=all.
  • Consumer가 메시지를 소비. orderId % 17 == 0이면 IllegalStateException으로 실패 시뮬레이션.
  • 실패 시 DefaultErrorHandler + FixedBackOff(500ms, 3)가 재시도, 한계 초과 시 DeadLetterPublishingRecoverer가 livelab.orders.DLT로 라우팅.
  • DLT 옵저버 컨슈머가 별도 그룹(livelab-orders-dlt-observer)으로 DLT를 카운트.
  • UI는 500ms 간격으로 /api/kafka-demo/status를 폴링해 진행 상태 라이브 갱신.
