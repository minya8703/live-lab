U4 · Redis 캐시 라이브 데모

Redis 캐시 + Fallback — 캐시 인프라가 죽어도 시스템은 안 죽는 패턴

Postgres 100,000건에 대해 카테고리별 집계 쿼리 (GROUP BY · 인덱스 의도적으로 미사용)를 캐시 없음 vs Redis 캐시로 같은 환경에서 실측합니다. Redis 장애 시에는 CacheErrorHandler로 DB 직접 조회 자동 fallback.

⚖ 이 데모의 trade-off (의식적 선택)

현재GenericJackson2JsonRedisSerializer + 단일 Redis 인스턴스 + TTL 60초.

한계 1JSON 안에 @class 패키지 경로가 함께 저장됨 → MSA 전환 시 다른 서비스에서 역직렬화하면 ClassCastException 위험.

한계 2Cache Stampede 미대응 — Redis 가 진짜 다운되면 동시 요청 수천 개가 Postgres 로 한 번에 쏟아져 DB 자체가 도미노로 무너질 수 있음.

엔터프라이즈급(1) Jackson2JsonRedisSerializer<DTO> 로 타입 명시 → 패키지 의존성 끊기. (2) Resilience4j Circuit Breaker + Bulkhead 로 Fallback 구간 보호 — 일정 비율 실패 시 고정 응답 (Static Fallback) 반환. (3) Redis Sentinel/Cluster 로 고가용성.

현 사이트가 안 가는 이유(1)(2) 는 즉시 적용 가능 — 별도 Unit 의 *개선 비교 회고* 로 분리 예정. (3) Cluster 는 메모리 4 노드 필요해 t4g.small 무리.

첫 캐시 실행은 미스라 DB로 떨어집니다(첫 막대만 길어요). 두 번째부터 전부 히트. "캐시 비우기"로 다시 콜드 상태에서 시작할 수 있습니다.

아키텍처 결정 — Redis를 어디에, 어떤 자료구조로 쓰는가

  • 역할: Redis는 원본 저장소가 아니라 반복 비용이 큰 조회 결과를 가속하는 계층이다. Postgres를 Source of Truth로 유지하고, 캐시 미스 시 DB 조회 후 채우는 Cache-Aside 패턴을 선택했다.
  • 현재 자료구조 — String(Key-Value): category-stats::<카테고리>를 키로, 집계 DTO 전체를 JSON 값으로 저장한다. 한 키로 결과 전체를 함께 읽고 만료시키는 조회 모델이므로 부분 필드 갱신용 Hash보다 단순하고 원자적인 구조가 맞다.
  • 다른 자료구조의 선택 기준: 객체 일부를 자주 갱신하면 Hash, 중복 없는 소속·권한 판별이면 Set, 점수 기반 순위·시간순 조회면 Sorted Set, 소비자 그룹이 필요한 이벤트 처리면 Stream을 검토한다. 자료구조는 기술 선호가 아니라 접근 패턴으로 결정한다.
  • 키·TTL: 도메인과 조회 조건이 드러나는 네임스페이스 키를 사용하고 TTL 60초로 성능과 신선도의 경계를 정했다. 실제 업무에서는 환율·마스터 데이터처럼 변경 주기와 stale 허용 시간에 따라 TTL을 다르게 둔다.
  • 무효화·일관성: 쓰기 성공 뒤 관련 캐시를 @CacheEvict한다. 캐시와 DB의 원자적 동시 갱신보다 DB 정합성을 우선하며, 짧은 eventual consistency가 허용되는 조회에만 캐시를 적용한다.
  • 장애 경계: Redis 오류는 CacheErrorHandler에서 격리해 DB로 fallback한다. 다만 대규모 트래픽에서는 fallback 자체가 DB를 압박하므로 Circuit Breaker·Bulkhead·TTL jitter·요청 병합으로 stampede까지 함께 막아야 한다.

이 데모가 실제로 무엇을 측정하나요?

  • SELECT sub_category, count, avg(price), min, max FROM product WHERE category = ? GROUP BY sub_category — Postgres 16에서 인덱스 없이 풀스캔.
  • 응답 시간(ns) → ms 변환 후 통계: 평균·최소·최대.
  • 캐시 키: category-stats::<카테고리명> · TTL 60s · 직렬화 GenericJackson2JsonRedisSerializer.
  • Redis 장애 시 CacheErrorHandler가 예외를 삼키고 @Cacheable이 캐시 미스로 처리 → DB 직접 조회로 자동 fallback.
