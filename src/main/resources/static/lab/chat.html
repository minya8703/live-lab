민야령의 경력에 직접 물어보세요

Spring AI 추상화 위 Google Gemini 2.5 Flash. 경력 데이터에 없는 영역은 "없다"고 답하고, 대신 인접 경험과 현재 방향성을 함께 안내합니다.

⚖ 이 챗봇의 trade-off (의식적 선택)

현재단일 LLM (Gemini 2.5 Flash) · 시스템 프롬프트에 경력 마크다운 전체 주입 · 환각 차단은 *없는 경험은 "없다"* 룰로.

한계 1토큰 사용량/비용이 외부에 노출 안 됨 — abuse 또는 트래픽 spike 시 비용 가시화 부재.

한계 2단일 모델 의존 — Gemini API 장애 시 fallback 없음.

엔터프라이즈급(1) 다중 모델 fallback (Gemini → Haiku 같은 chain) — Spring AI 의 추상화로 swap 자유. (2) 토큰 사용량 Prometheus 메트릭 + 일일 비용 대시보드. (3) IP 단위 rate limit + Cloudflare WAF 로 abuse 차단. (4) 프롬프트 캐싱으로 같은 컨텍스트 반복 호출 시 비용 90% 절감.

현 사이트가 안 가는 이유학습용 단일 모델이 단순함. 다중 모델·메트릭·rate limit 은 *코드 늘리지 않는 패턴 검증* 목적의 별도 Unit 으로.

안녕하세요. 민야령의 경력 Q&A 챗봇입니다.

Kafka 운영, 한샘 EAI, MSA 설계 경험 등 무엇이든 물어보세요. AWS 같은 직접 경험이 없는 영역은 솔직히 "없다"고 답합니다.
