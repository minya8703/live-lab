민야령의 경력에 직접 물어보세요

Spring AI 추상화 위 Google Gemini 2.5 Flash. 경력 데이터에 없는 영역은 "없다"고 답하고, 대신 인접 경험과 현재 방향성을 함께 안내합니다.

⚖ 이 챗봇의 trade-off (의식적 선택)

현재단일 LLM (Gemini 2.5 Flash) · 경력 마크다운 전체 주입 · answer/sources/grounded JSON 계약 · source ID 존재 검증 · prompt attack 입력/출력 정책 · peer 주소 기준 1시간 fixed window 20회 제한.

근거 검증grounded=true 답변은 실제 경력 Markdown 파일을 1개 이상 제시해야 한다. JSON 형식 오류·빈 출처·존재하지 않는 파일명은 사용자에게 노출하지 않고 보류 응답으로 전환한다.

공격 회귀지시 무시·프롬프트 탈취·허위 경력 생성·민감 의견 요청을 LLM 호출 전에 거부하고, 내부 프롬프트 조각이 응답에 포함되면 source가 유효해도 폐기한다. 정상적인 보안 설계 질문은 허용 사례로 함께 테스트한다.

한계 1서버는 파일의 존재 여부까지 검증한다. 해당 파일 내용이 답변의 모든 문장을 의미적으로 뒷받침하는지는 아직 자동 판정하지 않는다. 정규식 입력 정책도 알려진 명시적 공격을 줄이는 1차 방어이지 완전한 탐지기가 아니다.

한계 2호출자가 위조할 수 있는 X-Forwarded-For는 신뢰하지 않는다. 그 대신 Cloudflare 뒤에서는 여러 사용자가 같은 peer 한도를 공유할 수 있으며, fixed window 경계에서 요청이 몰릴 수 있고 현재 상태는 단일 인스턴스 전용이다.

운영급 방향(1) 질문과 관련된 문서만 선택. (2) 인용 문장과 원문 구간의 의미 일치 검증. (3) 실제 모델을 사용하는 선택적 품질 평가. (4) 신뢰한 프록시의 실제 사용자 주소로 공유 한도 개선. (5) 토큰·지연·grounded 비율 메트릭.

현재 범위문서 수가 작아 전체 주입을 유지한다. 검색이나 embedding은 문서 증가로 비용·정확도 문제가 측정될 때 도입한다.
